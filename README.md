# 招聘海报多维表边栏

纯前端、记录优先的多维表海报工作台：React 19 + TypeScript + Vite + Semi UI。默认主界面是当前主记录、字段原始顺序和只读海报；Canvas 2D 生成 PNG，SVG 只在高级编辑中负责选框和拖拽交互。飞书 SDK 直接读写多维表。Vercel 只托管静态文件，没有渲染 API、应用密钥、Vercel Functions 或 Vercel Blob。

## 运行与验证

```sh
npm ci
npm run dev
# 完整静态门禁
npm run verify:static
# Chromium 浏览器验收（自动启动 Vite）
npm run test:browser
# 一键静态门禁 + Chromium
npm run verify
```

打开 `http://127.0.0.1:5178`。普通浏览器使用明确标记的“本地示例”，数据为虚构招聘记录；本地模式不调用飞书，也不代表真实平台验收。`?mode=feishu` 或 iframe 嵌入会启用真实 SDK，失败不会静默回退示例。

其他验收命令：

```sh
npm test
npm run test:coverage
npm run test:browser:firefox
npm run test:browser:webkit
npm run test:browser:matrix
npm run build
npm run check:budget
npm run pack
```

`npm run pack` 输出 `output/poster-sidebar.zip`。CI 配置在 `.github/workflows/ci.yml`，静态门禁与三浏览器矩阵分开执行。

## 工作区与记录

- **默认记录工作台**：左栏选择多维表记录，中间按 `getFieldMetaList()` 返回顺序显示当前主记录的完整字段和值，右侧显示无选框、无拖拽的只读海报。首屏没有模板管理、图层或字段映射控件。
- **主操作**：不进入高级页面即可预览 PNG、生成并写回当前记录。“批量生成”中的**一键生成写回**会扫描全表，只处理输出附件为空的记录，已有附件自动跳过；执行前显示扫描、跳过和待写回数量。勾选生成、全表生成和逐行结果也位于该次级区域。
- **高级编辑**：模板、底图素材、字体、图层、固定文字、位置与样式集中在第一层高级页；返回记录页不会丢失草稿、分页、搜索、勾选或任务状态。
- **字段映射**：文字图层绑定、底图来源字段和输出附件字段统一收进第二层高级页。高级编辑只显示映射摘要，固定文字和样式不需要进入映射页。
- 首次分别选择业务数据表和配置数据表；连接指针按 Base 保存，重开恢复。已有配置表只补 `配置键`、`配置值` 文本字段，只有明确选择新建才建表。
- 字段、底图和输出字段始终使用稳定 ID，不随宿主当前选表隐式变化。切换数据表、模板、记录或底图来源时，未保存修改会先显示处理选择。
- 工作区元数据与记录分页分离。首屏只读一页；“加载更多”增量读取，搜索只针对已加载记录并明确标注范围。
- 当前预览记录与批量勾选记录分开。批量支持当前记录、勾选记录和全表；全表按需读取并二次确认，不再默认全表加载。

## 模板与编辑

- 文字框支持拖动、缩放、键盘微调、撤销/重做、固定文字、字体、字号、行数、行距、颜色和对齐；字段绑定只在字段映射页修改。
- 图层支持多选、锁定、上下层级、左/右/顶/底/居中对齐及横向/纵向分布。数组顺序就是绘制顺序；锁定后只能通过明确的解锁动作恢复编辑。
- 固定模板支持复制、删除、保存恢复；ZIP 模板包支持导入/导出，内含声明 JSON 与原始素材字节，不使用 base64。导入时重新计算素材 ID 并生成新模板 ID。
- 内置 Noto Sans SC 粗体使用全字符集 WOFF2；旧模板中的 OTF 仍可读取。上传支持 OTF、TTF、WOFF、WOFF2，字体失败不会静默换字体。
- 底图字段支持附件或附件查找引用，每行必须恰好一张 PNG/JPEG，等比填充、居中裁剪。来源模板保存在来源记录的 `海报模板配置` 与 `海报字体` 中。
- 移动页签支持方向键；画布支持单指平移、双指缩放、键盘缩放手柄。关键触控目标至少 44px，并支持减少动态效果设置。

## 生成、写回与错误语义

预览和导出共享排版规则，最小字号仍溢出时正式输出失败。PNG 写回只替换目标附件单元格，不修改其他业务字段。飞书模式可读取当前记录输出附件，本地示例可下载全部示例输出。“未写回”仅指当前选定输出附件单元格为空，与本机是否下载过文件无关；扫描候选行会再次串行核对实时附件版本。

批量不是跨行事务：先预检，再逐行渲染、串行写入。结果面板持久区分成功、预检失败、渲染失败、写入失败、附件冲突、结果未知和已停止。

- “停止后续”不声称取消正在执行的 SDK 写入。
- 写入结果未知或附件冲突不会自动重试。
- 只有明确未执行或写前失败的记录可安全重试。
- 模板、配置和输出附件使用乐观修订/快照检查；这不是跨端原子事务，冲突时必须人工核对。

本地持久化使用 IndexedDB 的 ArrayBuffer 二进制格式，读取时重建 Blob，兼容 WebKit；不是 base64，也兼容旧数据库中的 Blob。临时附件 URL 不作为持久身份，素材按 BLAKE2b 内容摘要去重。

## 工程质量

- 单应用分层：`app / application / features / domain / data / rendering / ui`，不引入 monorepo、Redux、React Query 或后端。
- `npm run check:architecture` 约束依赖方向；ESLint 覆盖 TypeScript、Hooks 和关键 a11y 规则，Prettier 做格式门禁。
- 核心覆盖率门禁为行 90%、分支 80%、函数 90%。当前实测均超过门禁。
- Chromium 验收含桌面/窄屏 axe、编辑交互、模板包、批量、PNG 像素基线和失败 trace；WebKit 使用相同功能与 axe 用例。
- 构建预算限制首屏/总 JS、CSS、最大 chunk、字体与示例底图字节。当前首屏 JS 和 CSS 的 gzip 大小分别约 194 KB 和 24 KB。首次进入工作区可以先阅读记录，预览就绪后再生成海报。

详细架构与验收记录见 [前端优化说明](docs/frontend-optimization.md)，部署见 [静态部署与宿主验收](docs/static-deployment.md)，复用取舍见 [复用调研](docs/reuse-research.md)。

## 边界

- `.source-poster-web` 与 `docs/source-audit.md` 是历史审查资料，不是当前运行架构。
- 当前没有 SVG 海报导入/导出，也没有业务记录增删改 UI；SVG 只用于编辑覆盖层。
- 真实飞书权限、附件 CORS、Lookup、字体兼容、实际单元格写入和 CSP 嵌入仍必须在宿主验收。
- 本机 Firefox 159 在 profile 创建阶段启动失败，未标记为通过；Chromium 与 WebKit 的 32 项验收均已通过。CI 矩阵保留 Firefox，不跳过。
