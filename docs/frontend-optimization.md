# 前端优化说明（2026-11-18）

## 目标形态

保持单应用与纯静态部署，借鉴三点检验的模块门面、同步互斥、请求代际、有界缓存和静态门禁，以及 PackVista 的动作状态、任务快照、逐项结果和结构化诊断。没有照搬 monorepo、RBAC、React Query、服务端队列或大型 App。

```text
src/
  app/            # Error Boundary、Semi ARIA 与 ResizeObserver 兼容
  application/    # 操作锁、动作状态、批量编排、模板包与 ID 重绑定
  features/       # workspace / editor / records / batch
  domain/         # 类型、几何、排版、图层、校验、素材规则
  data/           # local / feishu 适配器；feishu 子模块拆分
  rendering/      # 共享 Canvas renderer 与有界资源缓存
  ui/             # EditorStage 与通用控件
```

依赖方向为 `app/features → application → domain`，`data/rendering → application/domain`。`PosterRepository` 是稳定端口，本地与飞书实现可替换。记录页只读预览与高级 EditorStage 共用 renderer，不重复解码字体和图片。

## 记录优先信息架构

- 默认 `records`：记录列表、当前主记录字段和只读海报。字段详情严格遍历 `WorkspaceContext.fields`，展示值覆盖数字 `0`、空值、多选、Lookup 和附件文件名；不根据值对象键序或字段名重排。
- 主按钮“预览 / 生成并写回”直接在记录页完成当前记录操作。批量勾选与任务收据默认收起；“一键生成写回”扫描全表并只处理输出附件为空的记录，已有附件按摘要跳过、候选行串行复核实时版本，确认框展示总数/跳过数/待写回数。输出字段已有配置时无需进入设置页。
- 第一层高级 `template`：模板、素材、图层、固定文字、位置与样式。记录页往返不重置分页、搜索、勾选、草稿、历史或任务。
- 第二层高级 `mapping`：文字图层绑定、底图来源和输出附件。PropertyPanel 不再常驻字段绑定下拉，固定文字和样式仍留在第一层。
- 记录页不响应隐藏模板撤销；任务运行中禁止切换主记录，输出读取与安全重试使用任务行快照。
- 字段顺序承诺 SDK 字段元数据数组顺序；宿主具体视图的可视列顺序仍需真实飞书验收。

## 数据安全

- 同步 `OperationLock` 阻止同渲染周期重复操作；按钮可用性与阻断原因由纯函数统一计算。
- 未保存导航守卫覆盖模板、记录、来源、数据表和刷新；来源读取使用请求代际，旧结果不得覆盖新草稿。
- 模板、来源配置、工作区配置使用 `updatedAt` 乐观修订；输出附件使用元数据快照。检查不是跨端原子锁，冲突需要人工处理。
- 模板和配置不是同一事务，每一步成功后立即更新本地对应状态，避免部分成功被误报为全部未保存。
- 批量预检后才逐行渲染与串行写入，逐行保留结果。停止只影响后续行；未知写入和附件冲突不自动重试。

## 功能完成面

- 记录：分页/增量加载、已加载搜索、预览选择与批量勾选分离、全表按需读取与确认。
- 模板：复制、删除、修订冲突、ZIP 导入导出、内容哈希重绑定与重复别名去重。
- 编辑：多选、锁定、层级、对齐/分布、键盘缩放、单指平移、双指缩放。
- 输出：当前记录飞书附件查看/下载、本地全部示例附件、逐行结果和安全重试。
- 体验：标准 tab、非模态属性浮窗、焦点恢复、44px 关键目标、减少动态效果、桌面/窄屏 axe。

## 性能与资源

- `RequestCache` 同键合并、TTL、失败淘汰、代际失效，并增加 128 条 LRU 与 32MiB 默认字节上限；Blob 按实际大小计量。
- `Intl.Segmenter` 与排版结果有界复用；未引用旧底图不再进入保存包。
- 哈希在一次性 Worker 中执行，完成/失败/超时均终止；不支持 Worker 时回退主线程。
- 所有附件下载统一 20 秒超时和 20MiB 流式限制；图片另有 36MP 与 10000px 边长限制。
- ZIP 先检查中央目录、文件数、路径和展开总大小，再解压，拒绝路径穿越和未声明素材。
- IndexedDB 使用 ArrayBuffer 保存二进制并兼容旧 Blob，解决 WebKit `Error preparing Blob/File data`，不是 base64。
- ResizeObserver 在宏任务中按元素合并最新尺寸。编辑面板按需加载，预览按帧合并重绘。预览长边限制为 2048 px，PNG 仍按模板原始像素导出。

## 本轮布局与加载审计

桌面并列展示记录、字段和海报。在 768 和 1024 px 宽度下分别检查了三列边界和编辑工具。320 × 568 px 下限制记录列表高度，首屏能看到当前主记录标题。批量结果每页显示 20 条，43 条记录的浏览器用例覆盖末页和跨页重试。

对比使用修改前后两个本地生产构建、同一份示例数据和 Chromium 独立冷缓存上下文，从点击“查看记录”起计时。两种构建交替运行，各取中位数。

| 条件 | 指标 | 修复前 | 修复后 |
| --- | --- | ---: | ---: |
| 1 MiB/s 下载、35 ms 延迟，3 次 | 显示当前记录字段 | 9.96 秒 | 0.05 秒 |
| 同上 | 首张海报可见 | 10.02 秒 | 8.02 秒 |
| 本机不限速，5 次 | 显示当前记录字段 | 50 ms | 48 ms |
| 同上 | 首张海报可见 | 107 ms | 157 ms |

首次进入会按需读取全字符集 WOFF2。它比原先实际请求的 OTF 少 2,127,332 字节。限速时首张海报仍需下载底图和完整字体，本机不限速的冷启动首张海报增加约 50 ms。字体延迟、首次请求失败和原页重试均有浏览器回归。原始样本见[加载测量](../artifacts/loading-audit.json)。

首屏 JS 由 207,156 B 降至 194,016 B，CSS 由 83,325 B 降至 23,823 B。全部 JS 增至 546,177 B，含按需编辑面板、模板包 Worker 和兼容入口。

- 全表按页串行扫描，扫描可停止。提交补空任务及安全重试均沿用扫描确认的空版本，仓储在写入前复核。模拟 1,000 行、即时返回的渲染和仓储操作时，进度快照由 4,001 次降为 2 次。真实任务按经过时间发布进度并保留最终逐行收据。
- 读取飞书输出附件列表仅取元数据，点击文件时才获取 URL 和字节。来源附件按 token 索引，已验证素材复用同一 Blob。分页更新保留当前底图来源草稿。
- 浏览器在 Worker 中处理 ZIP 导入导出。本地版本检查与写入处于同一个 IndexedDB 事务，飞书输出继续采用串行写入与乐观版本校验。

## 验证证据

- 146 个单元测试通过。
- 核心覆盖率：行 95.83%、分支 88.23%、函数 96.34%；门禁为 90/80/90。
- Chromium：32 项通过，含记录首页与高级编辑的桌面/窄屏 axe、字段顺序、三层导航和 PNG 像素基线。
- WebKit：32 项通过，含相同功能、axe 和持久化兼容验证。
- TypeScript、ESLint、架构检查、生产构建和字节预算均通过。
- Firefox：本机 Playwright 在 profile 创建阶段连续三次失败，未完成验收；CI 不跳过。
- 真实飞书宿主与 Vercel 部署未由本轮自动化验证，按 `docs/static-deployment.md` 的发布门禁执行。

失败时浏览器脚本保存 `artifacts/browser-trace-<browser>.zip`、截图和 JSON 报告。`UPDATE_BASELINE=1 npm run test:browser` 仅用于明确接受新视觉基线后更新 `tests/fixtures/poster-baseline.png`，日常使用不得用更新基线掩盖差异。
